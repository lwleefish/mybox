# PLAN 01-04: 事件循环集成 + macOS 平台适配 + 测试模块（Walking Skeleton）

## Overview

本 plan 交付 Phase 1 的 Walking Skeleton 端到端能力："用户启动 mybox，看到托盘图标（无 Dock 项），按注册的全局热键 Cmd+Shift+T，测试窗口出现"。把 01-02（EventBus/WindowManager/Renderer）与 01-03（Hotkey/Config/Tray）接入 winit 事件循环，实现 App/AppBuilder、AppEvent 事件命名空间、macOS Accessory 激活策略（FRMW-06）、热键/托盘/菜单事件转发（FRMW-04）、TestModule（FRMW-01 端到端）。

**关键 research 决策（本 plan 锁定）：**
1. **ApplicationHandler + with_user_event**（RESEARCH §4）：`EventLoopBuilder::with_user_event::<AppEvent>()`，App 实现 `ApplicationHandler<AppEvent>`。
2. **macOS Accessory 模式**（RESEARCH §0.3/§6.1）：`EventLoopBuilderExtMacOS::with_activation_policy(ActivationPolicy::Accessory)`——**无需 objc2**（FRMW-06）。
3. **D-08 调和**（RESEARCH §0.6/§4）：global-hotkey/tray/menu 的 `set_event_handler` 闭包通过 `EventLoopProxy::send_event(AppEvent::...)` 唤醒 `ControlFlow::Wait` 事件循环。AppEvent 是 mybox 自己的枚举，EventLoopProxy 仅作唤醒桥——不把热键/托盘合并进 winit 原生事件源，也不使用 `ControlFlow::Poll` 轮询。
4. **热键分发按 action 名**（RESEARCH §11 #3）：App 把热键 id 映射为 action 名后发 bus 事件 `{ from: "core", kind: "hotkey.triggered", payload: Framework(HotkeyTriggered { id, action }) }`，模块订阅 `EventFilter::kind("core", "hotkey.triggered")` 检查 action。
5. **主线程职责**：HotkeyManager::init()、TrayManager::build()、窗口创建都在主线程（macOS 要求 + winit 绑定）。模块的窗口请求通过 WindowManagerHandle 的 crossbeam channel 入队（任意线程 send、非阻塞），入队后经 `AppEvent::WindowRequested` 脉冲唤醒 `ControlFlow::Wait` 循环（**crossbeam send 本身不唤醒 Wait 循环——W3**），App 在主线程 `about_to_wait()`（回调持有 `&ActiveEventLoop`）中 drain 并执行（01-04-03）；其它主线程操作经 UiThreadProxy 的 AppEvent::Ui 转发（FRMW-05）。
6. **配置热键启动注册（W1）**：run() 在 HotkeyManager::init() 后遍历 config.toml 的 `[hotkeys]` 节逐条 `register_str`——实现 RESEARCH §2.4 "从配置读取热键、注册、记录 id→action" 生命周期步骤，否则成功标准 2（Cmd+Shift+T 触发窗口）无法达成。
