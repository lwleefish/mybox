# PLAN 01-02: 事件总线 + 窗口管理器 + 渲染后端

## Overview

在 01-01 定义的纯类型之上，实现三个核心系统：EventBus（FRMW-02：pub/sub 广播分发 + FRMW-05：后台线程分发不阻塞事件循环）、WindowManager（FRMW-03：Overlay/Floating/Panel 三种窗口的创建/销毁/路由）、TinySkiaSoftbufferRenderer（D-01/D-02/D-03：纯 tiny-skia 渲染后端 + softbuffer 上屏）。本 plan 与 01-03 并行（同为 Wave 2），不依赖热键/托盘/配置。

**关键 research 决策（本 plan 锁定）：**
1. **事件分发位置**（RESEARCH §2.2 推荐项 + §11 #2）：采用 **bus 工作线程分发 + UiThreadProxy 转发**。bus 线程收到事件后分发给纯逻辑 handler；触碰 winit 窗口的 handler 通过 `ctx.ui().run(Box<dyn FnOnce + Send>)` 转发到主线程。保持 D-04 的"后台线程接收并分发"字面语义，事件循环只处理 UI 与渲染（FRMW-05）。
2. **crossbeam-channel unbounded**（RESEARCH §7）：`emit()` 只做 send，永不阻塞。
3. **WindowManager 主线程绑定**：WindowManager 持有 `winit::Window`（非 Send），存放在 App（ApplicationHandler）内。模块通过 `WindowManagerHandle` 入队 WindowRequest，主线程在下一循环迭代执行（01-04 接线；本 plan 提供 handle 的 channel 基础设施）。
4. **Overlay 透明**（RESEARCH §0.5）：softbuffer 在 macOS 无逐像素 alpha。本 plan 用 `with_transparent(true)` 窗口属性 + 不透明测试内容（D-09 批量创建签名仅定义，实现在 Phase 2）。
5. **egui 推迟**：本 plan 的 Renderer 为纯 tiny-skia。

## threat_model

| ID | Threat | Severity | Mitigation (in this plan) |
|----|--------|----------|---------------------------|
| T-1-04 | 事件 handler 恐慌导致 bus 线程崩溃 | low | bus 工作线程对每个 handler 调用用 `std::panic::catch_unwind` 包裹（或文档约定 handler 不 panic）；分发循环不死。 |
| T-1-05 | 事件洪泛导致内存无限增长 | low | unbounded channel 语义记录于代码注释；Phase 1 事件量极小；后续模块增多时改 bounded + 降载（v2）。 |
| T-1-06 | 渲染像素越界（w/h 与 buffer 长度不匹配） | low | present() 按 buffer 实际 width×height 截断复制，不假设 pixmap 与 buffer 同尺寸（RESEARCH §10.5 已 take(w*h)）。 |
