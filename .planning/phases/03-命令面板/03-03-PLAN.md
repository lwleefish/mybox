<objective>
修复 GAP-1（BLOCKER）：热键重复唤出失败——真实桌面上第二次及之后唤出的面板一闪而过（立即关闭）。

Purpose: 根因有二，均为真机时序缺陷（headless E2E 全绿因此漏过）：
1. **热键双报**（主因，依赖源码已证实）：global-hotkey 0.8.0 的 macOS 后端同时注册 `kEventHotKeyPressed` 与 `kEventHotKeyReleased`（registry src: global-hotkey-0.8.0/src/platform_impl/macos/mod.rs:324-332），`App::on_hotkey`（app.rs:314-328）不检查 `e.state` 把两者都转发成 bus `hotkey.triggered` → 一次物理按键产生两次 toggle（按下=summon、松开=close 翻转）。第一次按压因按住期间面板可见而"正常"，快速敲击即闪退。headless 测试注入的合成事件无 state 双报，因此全绿。
2. **建销配对跨模块污染 + 异步竞态**（gap 所指 pending_close 配对缺陷）：palette 在 init 订阅广播 `core/window-created`（lib.rs:106-120），对**任何模块**创建的窗口无条件执行 consume_pending_close→destroy 或 set_window_id——capture overlay 的创建会覆盖 palette 的 window_id（后续 toggle 误销毁 overlay），palette 的 pending_close 也可能误吞并销毁他模块窗口；且总线异步投递使 close 与 window-created 之间存在固有竞态。改为每窗口 `WindowSpec.on_created` 主线程同步回调后，配对只属于 palette 自己的窗口。

Output: core 热键状态过滤 + WindowSpec.on_created 加性扩展点 + palette 配对归属修复 + 单元/集成回归 + E2E `consecutive_summon_close` 探针（verify-phase 可在桌面会话重跑）+ REQUIREMENTS.md PAL-01 同步。
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS 全局热键监听线程 → App 事件循环 | global-hotkey 的 Pressed/Released 事件流进入 `AppEvent::Hotkey`（本地 OS 事件，非网络输入） |

| 主线程 create_window → session 配对 | `spec.on_created` 回调写入 PaletteSession 状态 |
