<objective>
修复 GAP-4（hover 高亮与文字区域错位）与 GAP-5（鼠标点击命令项无反应）。UAT 判断"疑似同源"部分成立：两缺陷同位于 `draw_command_row` 的交互/绘制架构，但根因是两个独立缺陷的组合，合并为一个计划修复：

1. **GAP-4 根因类（绘制/交互坐标系混用 + 行内布局越界）**：(a) 行矩形在 ScrollArea **内容 ui** 中分配（内容坐标空间随滚动偏移平移——egui-0.30.0 scroll_area.rs 源码：`content_max_rect = inner_rect.min - state.offset`），而高亮/文字用**外层 CentralPanel painter**（`ui.painter_at(ui.clip_rect())`，屏幕坐标空间）绘制——两坐标系仅在 offset==0 时重合；(b) 行高按 48px 精确公式计算（window_height），但 `allocate_rect` 按 `rect + item_spacing.y`（默认 3.0）推进光标，5 行内容 = 252px > 240px 视口 → 幻影滚动，`scroll_to_rect` 在 ↓/↑ 导航时激活非零偏移；(c) 行内垂直布局越界：name 位于 row.top+12+8=+20，desc 位于 name 底（14px×1.3=18.2）+4 → desc 底部 ≈+57.8 > 行高 48，描述文本压入下一行。
2. **GAP-5 根因（功能缺失）**：行仅 `Sense::hover()`，无任何 `clicked()` 分支、无点击→执行接线——点击永远不可能产生任何效果。这不是命中区域问题，是交互功能未实现。

Output: `draw_command_row` 重写（content-ui painter + `ui.interact(Sense::click)` + 点击执行 + 布局修正）+ `ui::draw` 签名扩展（windows/ui_proxy）+ item_spacing 归零 + headless 交互单测 + E2E `hover_click_alignment` 探针。REQUIREMENTS.md 不改动（PAL-04 已 `[x]` Complete；本计划强化其交互呈现，无待更新状态）。
</objective>
