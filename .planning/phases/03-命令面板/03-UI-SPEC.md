# Phase 03 — UI Design Contract (命令面板)

> Visual and interaction contract for the command palette. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Adaptation note:** This is a native Rust desktop phase (winit + tiny-skia + egui), NOT a web phase.
> All values are adapted accordingly: colors as sRGBA hex, spacing/sizes in logical pixels (points),
> fonts as a system CJK stack, "component library" → egui 0.30. No shadcn/tailwind/CSS anywhere.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — not applicable (native Rust desktop; no web design system) |
| Preset | not applicable |
| Component library | egui 0.30 (introduced this phase, re-exported via mybox-core — CONTEXT D-01) |
| Icon library | none — text-only palette; no icons in any row or state |
| Font | System CJK stack: macOS `Hiragino Sans GB` (`/System/Library/Fonts/Hiragino Sans GB.ttc`, verified present on dev Mac); Windows `Microsoft YaHei` (`C:\Windows\Fonts\msyh.ttc`) — Windows font discovery deferred to Phase 4, same pattern as Phase 2 A4. egui defaults kept as ASCII/emoji fallback only. |

**HARD REQUIREMENT (CJK):** egui's built-in fonts contain **no CJK glyphs**. The palette MUST load the system CJK font into `FontDefinitions` and insert it as the **first** Proportional family, or all Chinese command names render as tofu boxes (□). Font bytes load via `std::fs::read`; weight 600 uses the ttc's bold (W6) face; weight 400 uses the regular (W3) face.

## Spacing Scale

Declared values (multiples of 4, logical px):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Vertical gaps above/below the status line; gap between name and description inside a row |
| sm | 8px | Gap between input box and list |
| md | 12px | Panel outer padding (all sides); row horizontal padding; input horizontal padding |
| lg | 16px | Reserved — not used this phase |
| xl | 24px | Status line height |
| 2xl | 48px | Input box height; command row height |
| 3xl | 64px | Empty-state / error-state block height |

Exceptions: `md = 12px` is a deliberate half-step between 8px and 16px — used only for panel outer padding and row/input horizontal padding, where 8px reads cramped and 16px wastes width in a 600px card. All values remain multiples of 4. Every spacing decision above uses only these tokens.

---

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Input text | 16px | 400 | 1.5 |
| Command name | 14px | 600 | 1.3 |
| Description | 12px | 400 | 1.3 |
| Status line / empty / error | 12px | 400 | 1.5 |

- Exactly 3 font sizes: **16 / 14 / 12px**. Exactly 2 weights: **400 / 600**.
- Keyword-highlighted characters (D-10) inherit the weight of the text they appear in (name 600, description 400) — only their **color** changes, never size or weight.
- All sizes are logical points (egui native unit). DPI conversion to physical pixels happens at the window-size boundary only.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#202020` | Panel background (the card), list area background |
| Secondary (30%) | `#404040` | Selected row background, scrollbar thumb |
| Secondary (elevated) | `#2E2E2E` | Input box background, hovered row background |
| Accent (10%) | `#FF6000` | Matched-keyword character highlight ONLY (name / description / the rendered keyword tag) |
| Destructive / Error | `#E5484D` | Error-state message text only — no destructive user actions this phase |

Text tokens:

| Token | Value | Usage |
|-------|-------|-------|
| `text_primary` | `#FFFFFF` | Command name, input text, empty-state heading |
| `text_secondary` | `#A8A8A8` | Descriptions, status line, error detail (≥4.5:1 on both `#202020` and `#404040`) |
| `text_placeholder` | `#6E6E6E` | Input placeholder, error-state hint line |
| `hairline` | `rgba(255,255,255,0.08)` | 1px card border (defines the card edge over arbitrary screen content) |
| `disabled` | 50% opacity | Whole list + input while executing (D-04) — applied as alpha, not a color swap |

**Accent reserved for:** matched-keyword character highlight in command name, description text, and the rendered keyword tag. **Nothing else.** Selected row uses `#404040` (secondary), never accent — this keeps the orange keyword highlight legible inside the selected row.

**Phase 2 consistency trace (D-09):** `#202020` = Phase 2 capture_checks dark fill; `#404040` = Phase 2 toolbar button surface; `#FFFFFF` = Phase 2 text/icon color; `#FF6000` = Phase 2 annotation/active-tool accent. All four are carried forward verbatim so the palette reads as the same product.

## Panel Geometry & Window Behavior

| Property | Value |
|----------|-------|
| Width | **600 logical px fixed** (D-11); physical = `round(600 × scale_factor)` |
| Height (Idle/Filtering) | `80 + 48·n` where `n = min(visible_commands, 10)` → **128px (1 row) … 560px (10 rows)** |
| Height (Empty / Error) | **144px fixed** (empty/error block replaces the list) |
| Height (Executing) | `112 + 48·n` → **160px … 592px** (status line adds 32px, list stays visible but dimmed) |
| Corner radius | Panel **12px**; input box **8px**; selected row **8px** |
| Card border | 1px `rgba(255,255,255,0.08)` |
| Background | **Opaque** `#202020` (no transparency — guarantees text contrast over any wallpaper) |
| Shadow | None (borderless window; the radius + hairline border provide the card feel) |
| Position | **Centered on both axes of the active monitor** — SPEC req 3. "Active monitor" = the monitor containing the cursor at summon time; the two formulations are treated as the same monitor. |
| Window kind | `WindowKind::Floating` → borderless + always-on-top (core profile, window.rs); **non-resizable** (borderless = no resize affordance; spec sets fixed `inner_size`) |
| Lifecycle | **Build-on-summon / destroy-on-close** (D-06) — fresh window per invocation, no hidden reuse |
| Focus | Input focused immediately on summon (core `focus_window` + egui text-edit focus) |

## Component Inventory (egui)

The executor implements exactly these six pieces; no other UI elements exist this phase.

| Component | egui mapping | Spec |
|-----------|--------------|------|
| `PaletteCard` | custom-painted root (egui `Frame::none()` + rounded-rect painter) | fill `#202020`, radius 12, hairline border, width 600, adaptive height per geometry table |
| `SearchInput` | `TextEdit::singleline` | height 48, bg `#2E2E2E` radius 8, 12px horizontal padding, text 16px/400 `#FFFFFF`, placeholder `输入命令…` in `#6E6E6E`, caret `#FFFFFF` |
| `CommandRow` | custom-painted row + `LayoutJob` for highlight | height 48, 12px horizontal padding, name 14px/600 `#FFFFFF` top, description 12px/400 `#A8A8A8` bottom, 4px name→description gap; selected = bg `#404040` radius 8; hovered = bg `#2E2E2E` radius 8; keyword highlight `#FF6000` via `TextFormat` in `LayoutJob`. Keyword-tier hit (pinyin etc., 03-10): append a ` · {keyword}` tag at the END of the description line — same 12px/400, hit chars `#FF6000` (UAT test 5 highlight target); the tag stays on the same line and never adds a row |
| `StatusLine` | `Label` | 24px tall, text 12px/400 `#A8A8A8`, copy `正在执行：{name}…`, 4px gaps above/below, shown only in Executing state |
| `EmptyState` | centered `Label` block | 64px block: heading 14px/600 `#FFFFFF` + body 12px/400 `#A8A8A8` (copy below) |
| `ErrorState` | centered `Label` block | 64px block: line1 14px/600 `#E5484D` + line2 12px/400 `#A8A8A8` + line3 12px/400 `#6E6E6E` (copy below) |
| Scroll | `ScrollArea::vertical()` wrapping the row list | thumb `#404040`, transparent track; visible only when >10 matches |

egui `Visuals` overrides (dark theme baseline): `panel_fill = TRANSPARENT` (card is custom-painted), `window_rounding = 12`, disable `window_shadow`, selection/stroke colors per the color table above.

## Visual Hierarchy (Focal Point)

Primary focal point: the **search input** — top of card, 48px tall, 16px text (largest type on screen), auto-focused on summon. Secondary anchors: `#FF6000` keyword highlight in rows, then `#404040` selected-row background. No other element may visually compete with the input.

## Interaction Contract

### States

| State | Rendering | Input enabled | Selection |
|-------|-----------|---------------|-----------|
| `Hidden` | no window | — | — |
| `Idle` (summoned, empty input) | input + full command list (registration order) | yes | **none** (no highlight; Enter executes the first command) |
| `Filtering` (non-empty input) | input + fuzzy-scored list, desc order | yes | **index 0** (resets on every input change) |
| `Empty` (no match) | input + EmptyState block | yes | none |
| `Executing` | input + StatusLine + dimmed list (50% opacity) | **no** (anti-reentrancy, D-04) | frozen |
| `Error` | input (disabled look) + ErrorState block | **no** — any key closes | none |

### Keyboard map

| Key | State(s) | Action |
|-----|----------|--------|
| Global `Cmd+Shift+Space` (Win: `Ctrl+Shift+Space`) | any | Toggle: Hidden→summon+focus; visible→close |
| Printable chars | Idle/Filtering/Empty | Append to input, re-filter, selection = 0 |
| `↑` / `↓` | Idle/Filtering | Move selection, **wrap around** at ends; auto-scroll to keep selection visible |
| `Enter` | Idle/Filtering | Execute selected command (or first when selection is none) → `Executing` |
| `ESC` | Idle/Filtering/Empty | Close, execute nothing (SPEC req 6) |
| Any key | Error | Close panel (D-05) |
| Global hotkey | Executing | Close panel (runner continues in background; its completion is ignored by the destroyed window) |

### State transitions

```
Hidden ──hotkey──▶ Idle ──type──▶ Filtering ──no match──▶ Empty
  ▲                  │                │                    │
  └──ESC/hotkey──────┴──ESC/hotkey────┴──ESC/hotkey────────┘
Idle/Filtering ──Enter──▶ Executing ──runner Ok──▶ Hidden
                              │
                              └──runner Err──▶ Error ──any key/ESC──▶ Hidden
```

### Lifecycle rules

1. **Screenshot exception (SPEC constraint):** for `开始截图`, the panel hides/closes **BEFORE** the capture runner triggers — the palette must never appear in a screenshot.
2. **Anti-reentrancy:** re-invoking the hotkey while a palette window exists closes it (never a second window). Consecutive summon/ESC 5× leaves zero orphan windows (acceptance criterion).
3. **Selection semantics:** open with empty input → no highlight; first `↓` selects index 0; every input change resets selection to index 0; Enter with no selection executes the first command (SPEC req 5).
4. **Sorting:** fuzzy score desc (name matches weight higher than description/keyword matches — planner's scoring parameters), ties keep registration order (deterministic).
5. **No system notifications** anywhere (D-05). All feedback is inside the panel.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Input placeholder | `输入命令…` |
| Primary CTA | `回车` (Enter) — 执行所选命令 (no button; keyboard is the only CTA) |
| Secondary actions | `↑/↓` — 选择命令；`ESC` — 关闭面板 |
| Executing status (locked, D-04) | `正在执行：{name}…` |
| Empty state heading | `没有匹配的命令` |
| Empty state body | `换个关键词试试，清空输入可显示全部命令` |
| Zero-commands fallback heading | `没有可用的命令` |
| Zero-commands fallback body | `应用尚未注册任何命令` |
| Error state line 1 | `执行「{name}」失败` |
| Error state line 2 | `{具体错误信息}` (runner error text) |
| Error state line 3 | `按任意键或 ESC 关闭` |
| Destructive confirmation | **none** — no destructive actions this phase. `退出应用` is a standard quit with no confirmation (consistent with the tray exit path, INFRA-02); it receives no destructive styling. |

### Command inventory (row content — all five commands ship this phase)

| Command (id) | Name | Description | Suggested keywords | Source |
|--------------|------|-------------|--------------------|--------|
| `capture.start` | 开始截图 | 选择屏幕区域并复制到剪贴板 | `截图`, `capture`, `screen` | capture module (PAL-02) |
| `builtin.quit` | 退出应用 | 退出 mybox 应用 | `退出`, `quit`, `exit` | framework builtin (D-12) |
| `builtin.open_config` | 打开配置目录 | 在文件管理器中打开 mybox 配置目录 | `配置`, `config` | framework builtin (D-12) |
| `builtin.restart` | 重启应用 | 重启 mybox 应用 | `重启`, `restart` | framework builtin (D-12) |
| `builtin.open_log` | 打开日志文件 | 打开 mybox 运行日志 | `日志`, `log` | framework builtin (D-12/D-13) |

Rules: every command has a non-empty name AND description (SPEC req 1); descriptions render in `#A8A8A8`; names render in `#FFFFFF` 14px/600. List order with empty input = registration order (builtins after module commands, stable).
