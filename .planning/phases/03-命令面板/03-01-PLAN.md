## Phase Goal

**As a** mybox 用户，**I want to** 按全局快捷键唤出屏幕中央的命令面板浮窗并看到全部已注册命令，**so that** 所有工具通过一个统一入口触手可及（本 plan 交付窗口形态 + 命令注册机制；模糊搜索与键盘执行由 03-02 叠加）。

<objective>
交付命令面板的第一条垂直切片：**全局热键 `Cmd+Shift+Space` → 屏幕中央 Floating 浮窗（egui 渲染）→ 列出全部已注册命令**。分三部分：(1) 核心命令注册系统——`Module::commands()` 接口 + `Command`/`CommandRegistry`/`BuiltinCommands`（4 个内置命令）+ AppBuilder 装配 + `core/app-exit` 退出通道；(2) 三个核心加性窗口扩展——`WindowSpec.on_event_win`（egui-winit 需要 `&Window`）、Floating 聚焦 + 不可 resize、macOS NSWindow 圆角；(3) 新 crate `crates/modules/palette`——唤出热键、建销生命周期（D-06）、egui→tiny-skia 软件光栅化、CJK 字体、活动显示器居中。

Purpose: 这是 Phase 3 的地基。没有命令注册机制，面板无数据可列（PAL-02）；没有 on_event_win 窗口访问，egui-winit 0.30 无法接入（D-03 的机制落点）；没有 palette crate 的渲染链路，面板无画面。
Output: mybox-core 新增 command.rs + 4 文件扩展；新建 mybox-palette crate（lib/session/position/fonts/raster/ui）；capture 模块注册「开始截图」命令；mybox-app 双路日志 + palette 注册。

⚠ **D-03 细化（用户批准 2026-08-14）**：egui-winit 0.30 的 `on_window_event`/`take_egui_input` 均需 `&winit::window::Window`，而 `WindowSpec.on_event` 闭包只收 `&WindowEvent`——「核心框架代码零改动」字面不可行的结论已获用户批准（03-CONTEXT.md D-03 细化，2026-08-14）。本 plan 按批准实施 6 个**加性**框架扩展点 C1-C6（与 Phase 2 的 `on_draw`/`WindowRequest::Redraw` 同类），全部不改动既有窗口/事件行为；egui 集成仍由 palette 模块自持有（D-03 的意图完整保留）。

⚠ **包合法性门禁已关闭**：03-RESEARCH Package Legitimacy Audit 已执行（slopcheck 0.6.1），egui 0.30.0 / egui-winit 0.30.0 / fuzzy-matcher 0.3.7 / pollster 1.0.1 / objc2-app-kit 0.3.2 全部 [OK]；xcap [SUS] 为 name-similarity false positive（Phase 2 已批准、已在 Cargo.lock，非新安装）。无需 blocking-human checkpoint，可直接 cargo add。
</objective>
