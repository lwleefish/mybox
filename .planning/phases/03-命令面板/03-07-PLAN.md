<objective>
修复 GAP-6：Ctrl+P / Ctrl+N 键盘导航缺失——当前 `on_palette_key`（lib.rs:371-421）只有 ArrowUp/ArrowDown 分支。两个 API 硬约束决定最小侵入方案（winit 0.30.13 源码已查证）：

1. **KeyEvent 无 modifiers 字段**：winit 0.30.13 的 `KeyEvent` 只有 physical_key/logical_key/text/location/state/repeat（event.rs:523-588，modifiers 是 winit 0.31 才加入的字段）——不能在 KeyboardInput 事件内直接读 Ctrl 状态。
2. **KeyEvent 不可外部构造**：`platform_specific` 字段 `pub(crate)`（03-02 deviation #2 已确立），合成键盘事件不可行——键盘路由必须保持"共享函数"形态。

方案：闭包经 `WindowEvent::ModifiersChanged`（可构造、可注入）跟踪修饰键状态存入 session（新窗口 summon 重置）；`on_palette_key` 签名增加 `modifiers: ModifiersState` 参数（headless 可测）；新增 Ctrl+P/Ctrl+N 守卫分支（`modifiers.control_key()` + logical_key 为 KeyP/KeyN 或字符 p/n）等价 move_selection(-1/+1)。普通 P/N 无 Ctrl 时守卫不满足，路由返回 false，字符照常进入 TextEdit（过滤语义不变）。

Output: session 修饰键状态 + 路由签名与分支 + 闭包接线 + headless 路由单测 + E2E `ctrl_pn_navigation` 探针（真实 ModifiersChanged 注入断言）。REQUIREMENTS.md 不改动（PAL-04 已 `[x]` Complete；本计划强化其导航键盘映射，无待更新状态）。
</objective>
